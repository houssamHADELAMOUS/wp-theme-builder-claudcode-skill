# WP Theme Builder — Claude Code Skill

**Make Claude Code build WordPress themes like a senior WordPress developer.**

A [Claude Code skill](https://code.claude.com/docs/en/skills) for freelancers, agencies
and site owners who want a custom WordPress theme that is secure, fast, accessible,
translatable and compliant with WordPress core rules and the WordPress.org Theme Review
requirements, whether the theme is for a client or for yourself.

Install it once, then simply say *"build me a WordPress theme for my client's bakery"*
and Claude asks the right discovery questions, picks the right theme architecture,
scaffolds a clean starting point, builds on it with every WordPress rule applied, audits
the result with real tools, and hands you a release-ready package.

## The idea

Most WordPress themes generated by AI (or written in a hurry) share the same problems:
unescaped output, `$_POST` used raw, no nonces, unprefixed functions that collide with
plugins, custom post types buried in `functions.php` so the client loses their content
when the theme changes, Google Fonts loaded without consent, `query_posts()`, hard-coded
`<script>` tags, no skip link, no focus styles, and a `style.css` header that WordPress
rejects.

Senior WordPress developers avoid all of this by habit. This skill turns those habits
into instructions Claude follows every time:

1. **Presentation in the theme, content structure in a companion plugin.** Post types,
   taxonomies, blocks and shortcodes go in a `<slug>-core` plugin so the client keeps
   their data when the design changes.
2. **Security is not optional.** Escape late, sanitize early, nonce plus capability on
   every write, prefix everything, never touch the forbidden-function list.
3. **The WordPress.org Theme Review rules are the quality bar**, even for a private
   client theme, because they are simply the definition of a well-built theme.
4. **Nothing ships unlinted.** Generated code passes PHPCS with the WordPress Coding
   Standards, the bundled audit, the Theme Check plugin and `theme.json` schema
   validation. Claude runs the tools and reports the output instead of claiming success.
5. **Accessible and fast by construction.** Skip link, landmarks, contrast, focus styles,
   deferred scripts, self-hosted fonts, conditional asset loading, Core Web Vitals targets.
6. **Hand-off is part of the job.** Versioning, changelog, `readme.txt`, editor guide,
   client-proofed editor settings and a clean release zip.

## Installation

### Windows (PowerShell)

```powershell
git clone https://github.com/houssamHADELAMOUS/wp-theme-builder-claudcode-skill.git
cd wp-theme-builder-claudcode-skill
.\install.ps1            # symlinks skill/ -> %USERPROFILE%\.claude\skills\wordpress-theme-builder
.\install.ps1 -Copy      # copy instead of symlink (used automatically if symlinks are not allowed)
.\install.ps1 -Uninstall # remove
```

Symlinks need Windows Developer Mode or an elevated shell; otherwise the installer copies
the folder, and you re-run `install.ps1` after pulling updates.

### macOS / Linux

```bash
git clone https://github.com/houssamHADELAMOUS/wp-theme-builder-claudcode-skill.git
cd wp-theme-builder-claudcode-skill
./install.sh              # symlinks skill/ -> ~/.claude/skills/wordpress-theme-builder
./install.sh --copy       # copy instead of symlink
./install.sh --uninstall  # remove
```

### Project-only install (share with your team)

Copy or symlink `skill/` to `<your-wordpress-project>/.claude/skills/wordpress-theme-builder`
and commit it. Everyone who opens the project in Claude Code gets the skill.

### Check it works

Start a new Claude Code session and type `/` — `wordpress-theme-builder` appears in the
list. It also triggers automatically whenever you talk about building, reviewing or
extending a WordPress theme.

## How to use it

You do not need special commands. Describe what you want in plain language.

### Building a new theme

> "Build me a custom WordPress theme for a law firm client. They have a Figma design
> (attached screenshots). The client will edit pages themselves but must not break the
> layout. They need a Team section and Case Studies."

Claude will:

1. Ask a short set of discovery questions (only the ones you have not answered).
2. Recommend block, classic or hybrid with a one-paragraph reason.
3. Run the scaffold script, creating the theme, a `<slug>-core` companion plugin for the
   Team and Case Studies post types, and the dev configs.
4. Build the design on top: `theme.json` tokens, templates, patterns, styles.
5. Run the audit script, PHPCS, schema validation and (if Docker is available) a local
   WordPress with Theme Check, fixing everything it finds.
6. Deliver the checklist with what was actually verified, plus hand-off notes.

Explicit invocation works too:

```
/wordpress-theme-builder new law-firm
```

### Auditing an existing theme

> "Is the theme in `wp-content/themes/acme` secure and WordPress-compliant?"

or

```
/wordpress-theme-builder audit
```

Claude runs the audit script and PHPCS against the folder, walks the Theme Review
checklist, and returns findings with `file:line`, severity and a concrete fix for each.
It never reports "passed" for a check it did not run.

### Extending an existing theme

> "Add a testimonials pattern and a `single-event` template to my theme."

Claude reads the theme's `style.css`, `functions.php` and `theme.json`, matches its
prefix, text domain and architecture, adds the feature using the existing design tokens,
then re-runs the audit.

### Child themes

> "Create a child theme of Twenty Twenty-Six for this client with a custom header."

Claude follows the child-theme rules: `Template:` header, correct parent/child style
loading, overriding only what is needed, and still keeps content types out of the theme.

### Running the scripts by hand

```bash
# What tools are available?
node ~/.claude/skills/wordpress-theme-builder/scripts/check-tools.js

# Scaffold a block theme with a companion plugin and dev configs
node ~/.claude/skills/wordpress-theme-builder/scripts/scaffold-theme.js \
  --type block --slug acme --name "Acme" --prefix acme --author "Your Agency" \
  --out ./wp-content/themes/acme --with-plugin

# Audit any theme folder (exit code 1 when errors are found)
node ~/.claude/skills/wordpress-theme-builder/scripts/audit-theme.js ./wp-content/themes/acme
node ~/.claude/skills/wordpress-theme-builder/scripts/audit-theme.js ./wp-content/themes/acme --json

# Real linting inside the generated theme
cd wp-content/themes/acme
composer install
vendor/bin/phpcs          # zero errors is the bar
vendor/bin/phpcbf         # auto-fix formatting

# Local WordPress with Theme Check + Query Monitor (Docker)
npx @wordpress/env start
npx @wordpress/env run cli wp eval-file /var/www/html/theme-check.php acme   # after copying scripts/theme-check.php in
```

Scaffold options:

| Option | Meaning |
| --- | --- |
| `--type block\|classic\|hybrid` | theme architecture (required) |
| `--slug` | folder name and text domain, lowercase-hyphen (required) |
| `--name`, `--author`, `--author-uri`, `--theme-uri`, `--description` | metadata for `style.css` and `readme.txt` |
| `--prefix` | function/handle/option prefix, at least 4 characters (default derived from slug) |
| `--wp-min`, `--php-min` | `Requires at least` / `Requires PHP` (defaults 6.7 / 7.4) |
| `--out` | target directory (default `./<slug>`) |
| `--with-plugin`, `--plugin-out` | also create the `<slug>-core` companion plugin |
| `--no-configs` | skip PHPCS/Composer/npm/wp-env/editorconfig files |
| `--force`, `--dry-run` | overwrite a non-empty folder / preview only |

## The workflow Claude follows

```
Step 0  Discovery      who edits, site type, content types, design source, host versions, plugins
Step 1  Theme type     block by default; hybrid for PHP control / ACF / page builders; classic for legacy
Step 2  Scaffold       scaffold-theme.js → clean, lint-passing starting point (+ companion plugin)
Step 3  Build          every line follows the non-negotiable rules in SKILL.md
Step 4  Audit loop     audit-theme.js → PHPCS → schema → wp-env + Theme Check → checklist, repeat until clean
Step 5  Hand-off       readme.txt, README.md, CHANGELOG, zip, editor guide, client-proofing
```

The rules in Step 3 are the heart of the skill. A few examples:

- Every `echo` goes through `esc_html()`, `esc_attr()`, `esc_url()`, `wp_kses_post()` or
  a self-escaping core function; `__()` and `_e()` are never printed raw.
- Superglobals are read as `isset()` → `wp_unslash()` → `sanitize_*()` → validate.
- Every state change verifies a nonce **and** `current_user_can()`.
- Everything in the global namespace carries the theme prefix.
- Assets are enqueued with a version and `strategy => defer`; fonts are self-hosted.
- No post types, taxonomies, blocks, shortcodes, SEO, analytics or forms in the theme.
- Classic themes include `wp_head()`, `wp_body_open()`, `body_class()`, `post_class()`,
  `wp_footer()`, `wp_link_pages()`, `title-tag` support and a skip link.
- Block themes use `theme.json` version 3, declare template part areas, set
  `"inherit":true` on archive Query Loops and keep translatable text in patterns.

## Block, classic or hybrid?

| | Block (FSE) | Classic | Hybrid |
| --- | --- | --- | --- |
| Templates | `templates/*.html` | PHP files | PHP files + `theme.json` + patterns |
| Client can edit header/footer visually | yes | no | optional |
| Page builders (Elementor, Bricks) | poor fit | good | good |
| ACF flexible layouts | awkward | natural | natural |
| Style variations / multi-brand | yes | no | partial |
| Direction of WordPress core | primary | maintained | transitional |
| Default recommendation | new sites | legacy constraints only | PHP control or existing sites |

The skill's decision matrix scores your answers and explains the choice.

## The audit script

`scripts/audit-theme.js` is a PHP-aware static checker written for environments where
PHPCS is not available. It lexes PHP (strings, comments, inline HTML) and reports
`file:line` findings with severity:

| Rule group | Examples |
| --- | --- |
| structure | missing `style.css` headers, bad version format, forbidden files, missing `readme.txt`/screenshot, screenshot size, `index.php`/`templates/index.html` |
| escaping | unescaped `echo`/`print`/`printf`/`<?=`, raw `__()`/`_e()`, ternaries and concatenations analysed part by part |
| input | superglobals without `wp_unslash` + sanitizer, `$_POST` without a nonce, `$_FILES` |
| prefix | functions, classes, namespaces, constants, handles, image sizes, options, transients, hooks, template-scope globals |
| assets | hard-coded `<script>`/`<link>`, remote CDNs and Google Fonts, bundled jQuery, `outline: none` without replacement |
| forbidden | `eval`, `base64_decode`, `query_posts`, `curl_*`, filesystem writes, `header('Location')`, deprecated functions, admin-bar removal |
| territory | `register_post_type`, `register_taxonomy`, `add_shortcode`, `register_block_type`, roles, analytics, SEO meta |
| hooks | classic required functions, `<title>` tag, `include` of templates, skip link, `<main>` |
| block | `theme.json` version and schema, template part areas, custom templates, delimiter balance, invalid attribute JSON, stray root content |
| i18n | text-domain mismatch, non-literal domain, missing domain, missing `translators:` comments |
| customizer / database / debug | `add_setting` without `sanitize_callback`, `$wpdb` without `prepare()`, `var_dump`/`console.log` |

It honours `// phpcs:ignore` comments, reads the prefix from `.phpcs.xml.dist`, and exits
with code 1 when errors remain. It is a fallback and a fast first pass; PHPCS remains the
authority.

## Customising the skill

- **Your agency's conventions**: edit `skill/SKILL.md` Step 3 (rules) and the templates in
  `skill/assets/templates/`. Keep `SKILL.md` under 500 lines; put detail in `references/`.
- **Default palette, fonts, spacing**: `skill/assets/templates/block/theme.json` and
  `classic/theme.json`.
- **Extra audit rules**: add entries to the `FORBIDDEN`, `PLUGIN_TERRITORY` or
  `DEPRECATED` lists in `skill/scripts/audit-theme.js`.
- **Different minimum versions**: `--wp-min` / `--php-min` at scaffold time, or change the
  defaults in `scaffold-theme.js` and the `Tested up to` values in the templates.
- After changing templates, re-run the regression: scaffold each type, run the audit and
  PHPCS, and make sure both stay clean.

When a new WordPress version changes theme APIs, update `references/theme-json.md`,
`references/block-theme.md` and the template headers.

## FAQ

**Does it work for WooCommerce sites?**
Yes. The theme stays presentation-only; WooCommerce template overrides for markup are
fine, and the skill guards plugin-provided features with `class_exists()`.

**Can I use Tailwind or Sass?**
Yes, through `@wordpress/scripts` (`package.json` is scaffolded). The skill insists the
build output is committed or built in CI, unused CSS is purged, and design tokens stay in
`theme.json`.

**Will the theme pass WordPress.org submission?**
The skill applies the required rules and Theme Check passes on the scaffold, but a human
review also checks design originality, licensing of every asset and accessibility. The
checklist covers those items so nothing is forgotten.

**Why a companion plugin?**
Because content types belong to the site, not the design. Switching themes must never
delete a client's projects, team members or testimonials.

**Does it replace PHPCS?**
No. The bundled audit is a fast, dependency-free first pass. Claude runs PHPCS whenever
PHP and Composer are available and treats it as the authority.
