# theme.json Reference (version 3)

`theme.json` is the single source of truth for design tokens and block defaults. It
applies to block themes fully and to hybrid/classic themes for the editor and CSS
custom properties.

## Skeleton and versioning

```json
{
	"$schema": "https://schemas.wp.org/trunk/theme.json",
	"version": 3,
	"settings": {},
	"styles": {},
	"customTemplates": [],
	"templateParts": [],
	"patterns": []
}
```

- Always `"version": 3` (WP 6.6+). Pin the schema to a release for stability:
  `https://schemas.wp.org/wp/7.0/theme.json`; `trunk` for the newest keys.
- Version 3 breaking changes vs 2:
  - `settings.typography.defaultFontSizes` (default `true`): when `true` core keeps its
    `small`…`xx-large` sizes and your same-slug entries are ignored. Set `false` to
    replace them with your own scale using those slugs.
  - `settings.spacing.defaultSpacingSizes` (default `true`): same for spacing presets
    `20`…`80`. Set `false` to define your own `spacingSizes` (or use `spacingScale`).
  - Fluid typography opt-in: with `fluid: true` and no `min`/`max`, core computes them.
- Cascade order (lower wins): core defaults → theme `theme.json` → child theme
  `theme.json` → active style variation → user Global Styles in the DB.

## settings

Settings control **what the editor lets users do** and **which presets exist**.

```json
"settings": {
	"appearanceTools": true,
	"useRootPaddingAwareAlignments": true,
	"layout": {
		"contentSize": "720px",
		"wideSize": "1200px",
		"allowEditing": true,
		"allowCustomContentAndWideSize": false
	},
	"color": {
		"palette": [
			{ "slug": "base", "color": "#ffffff", "name": "Base" },
			{ "slug": "contrast", "color": "#111111", "name": "Contrast" },
			{ "slug": "primary", "color": "#0055aa", "name": "Primary" },
			{ "slug": "secondary", "color": "#f3f4f6", "name": "Secondary" },

		"blockGap": true,
		"margin": true,
		"padding": true,
		"customSpacingSize": false
	},
	"border": { "color": true, "radius": true, "style": true, "width": true },
	"shadow": {
		"defaultPresets": false,
		"presets": [
			{ "slug": "card", "shadow": "0 2px 8px rgba(0,0,0,.08)", "name": "Card" }

	"position": { "sticky": true },

```

Notes:
- `appearanceTools: true` enables border, color.link, dimensions, position.sticky,
  spacing.blockGap/margin/padding, typography.lineHeight, background, shadow in one go.
- `useRootPaddingAwareAlignments: true` + `styles.spacing.padding` on root makes
  `alignfull` blocks bleed to the viewport edge while content keeps side padding. Set
  root padding with `left`/`right` only for this to work.
- `spacingScale` (`{ "operator": "*", "increment": 1.5, "steps": 7, "mediumStep": 1.5, "unit": "rem" }`)
  is the alternative to explicit `spacingSizes`.
- `custom` values become `--wp--custom--radius--sm` etc. Nest freely; camelCase keys are
  converted to kebab-case.
- Per-block `settings.blocks["core/x"]` overrides globals for that block only.
- Turning `custom*` and `default*` flags off is how you lock clients to your design
  system.

## styles

Styles set **defaults** for the site, elements, and blocks. Use preset variables, not
literals.

```json
"styles": {
	"color": { "background": "var(--wp--preset--color--base)", "text": "var(--wp--preset--color--contrast)" },
	"typography": {
		"fontFamily": "var(--wp--preset--font-family--body)",
		"fontSize": "var(--wp--preset--font-size--medium)",
		"lineHeight": "1.6"
	},
	"spacing": {
		"blockGap": "var(--wp--preset--spacing--40)",
		"padding": { "left": "var(--wp--preset--spacing--40)", "right": "var(--wp--preset--spacing--40)" }
	},
	"elements": {
		"link": {
			"color": { "text": "var(--wp--preset--color--primary)" },
			":hover": { "color": { "text": "var(--wp--preset--color--accent)" }, "typography": { "textDecoration": "none" } },
			":focus": { "outline": { "width": "2px", "style": "solid", "color": "var(--wp--preset--color--accent)", "offset": "2px" } }
		},
		"button": {
			"color": { "background": "var(--wp--preset--color--primary)", "text": "var(--wp--preset--color--base)" },
			"border": { "radius": "var(--wp--custom--radius--md)" },
			"spacing": { "padding": { "top": "0.75rem", "bottom": "0.75rem", "left": "1.5rem", "right": "1.5rem" } },
			":hover": { "color": { "background": "var(--wp--preset--color--accent)" } },
			":focus-visible": { "outline": { "width": "2px", "style": "solid", "color": "var(--wp--preset--color--contrast)", "offset": "2px" } }
		},
		"heading": { "typography": { "fontFamily": "var(--wp--preset--font-family--heading)", "fontWeight": "700", "lineHeight": "1.2" } },
		"h1": { "typography": { "fontSize": "var(--wp--preset--font-size--xx-large)" } },
		"h2": { "typography": { "fontSize": "var(--wp--preset--font-size--x-large)" } },
		"h3": { "typography": { "fontSize": "var(--wp--preset--font-size--large)" } },
		"caption": { "typography": { "fontSize": "var(--wp--preset--font-size--small)" } },
		"cite": {}
	},
	"blocks": {
		"core/site-title": { "typography": { "fontWeight": "800" }, "elements": { "link": { "typography": { "textDecoration": "none" } } } },
		"core/navigation": { "typography": { "fontWeight": "500" } },
		"core/quote": { "border": { "left": { "width": "4px", "style": "solid", "color": "var(--wp--preset--color--primary)" } } },
		"core/post-title": { "elements": { "link": { "typography": { "textDecoration": "none" } } } },
		"core/button": {
			"variations": {
				"outline": {
					"color": { "background": "transparent", "text": "var(--wp--preset--color--primary)" },
					"border": { "width": "2px", "style": "solid", "color": "var(--wp--preset--color--primary)" },
					":hover": { "color": { "background": "var(--wp--preset--color--primary)", "text": "var(--wp--preset--color--base)" } }
				}
			}
		},
		"core/group": {
			"css": "&.is-style-pfx-card { box-shadow: var(--wp--preset--shadow--card); border-radius: var(--wp--custom--radius--lg); }"
		}
	},
	"css": ".screen-reader-text { clip: rect(1px,1px,1px,1px); position: absolute !important; height: 1px; width: 1px; overflow: hidden; }"
}
```

- Elements: `link`, `button`, `heading`, `h1`–`h6`, `caption`, `cite`. Pseudo-classes on
  `link` and `button`: `:hover`, `:focus`, `:active`, `:visited`, `:focus-visible`.
- `styles.blocks["core/x"].variations.<style-name>` styles block-style variations
  (`is-style-<name>`), including core `outline` for buttons and your own registered ones.
- `css` property (root or per block) for small custom CSS; `&` refers to the block
  selector. Keep it short; larger CSS goes in enqueued files.
- `outline` support on elements for accessible focus rings.

## customTemplates, templateParts, patterns

```json
"customTemplates": [
	{ "name": "page-landing", "title": "Landing Page", "postTypes": [ "page" ] },
	{ "name": "blank", "title": "Blank Canvas", "postTypes": [ "page", "post" ] }
],
"templateParts": [
	{ "name": "header", "title": "Header", "area": "header" },
	{ "name": "footer", "title": "Footer", "area": "footer" },
	{ "name": "sidebar", "title": "Sidebar", "area": "uncategorized" }
],
"patterns": [ "hero-section-with-image", "footer-with-columns" ]
```

- `customTemplates[].name` must match a file in `templates/`.
- `templateParts[].area`: `header`, `footer`, or `uncategorized`.
- `patterns` lists pattern **slugs from wordpress.org/patterns** to bundle; usually leave
  empty for client themes.

## CSS custom properties generated by core

| Preset | Variable |
| --- | --- |
| Colour | `--wp--preset--color--{slug}` |
| Gradient | `--wp--preset--gradient--{slug}` |
| Font size | `--wp--preset--font-size--{slug}` |
| Font family | `--wp--preset--font-family--{slug}` |
| Spacing | `--wp--preset--spacing--{slug}` |
| Shadow | `--wp--preset--shadow--{slug}` |
| Duotone | `--wp--preset--duotone--{slug}` |
| Custom | `--wp--custom--{path--with--dashes}` |
| Layout | `--wp--style--global--content-size`, `--wp--style--global--wide-size` |
| Root padding | `--wp--style--root--padding-{top,right,bottom,left}` |
| Block gap | `--wp--style--block-gap` |

Utility classes: `.has-{slug}-color`, `.has-{slug}-background-color`,
`.has-{slug}-font-size`, `.has-{slug}-font-family`, `.has-{slug}-gradient-background`.
Use these in CSS and patterns; never re-declare the same value as a literal.

## Style variations

`styles/*.json` files with the same schema plus `"title"`. Partial: only the keys that
differ from the base. Keep preset **slugs** stable across variations. Block-style
variations in `styles/blocks/*.json` add `"blockTypes": ["core/group"]` and `"slug"`;
section styles use the same mechanism to restyle nested blocks in one go.

---

## WordPress 7.0 additions

- Pseudo-class selectors (`:hover`, `:focus`, `:focus-visible`, `:active`) directly on
  `styles.blocks["core/x"]` and on block style variations, not only on elements.
- `dimensions` gains `width`/`height` block supports and dimension presets.
- `typography.textIndent` and `typography.textColumns` supports.
- Fonts page under Appearance for all themes (font management moves out of Global
  Styles UI); classic themes get the Font Library too.
- `block.json` `apiVersion: 3` mandatory for custom blocks.

If `Requires at least` is below 7.0, do not rely on block-level pseudo-classes; use
`css` or a stylesheet instead.

## Rules and gotchas

- JSON only: no comments, no trailing commas. Validate against `$schema` (VS Code does
  this automatically; CI can use `ajv`).
- Slugs are lowercase, hyphenated, stable. Renaming a slug breaks saved content that
  references `has-{slug}-color`.
- Semantic slugs (`base`, `contrast`, `primary`, `accent`) beat descriptive ones
  (`blue`, `dark-gray`) because variations swap the values.
- Keep at least `base` and `contrast` with AA contrast (4.5:1).
- Do not put `!important` in `styles.css`.
- Font files referenced with `file:./relative/path` are resolved by core.
- Fluid typography needs `settings.typography.fluid: true`; then per-size `fluid: false`
  opts individual sizes out (small sizes should not shrink).
- `settings.layout` sizes are used by constrained layouts and `alignwide`/`alignfull`;
  without them nothing constrains.
- A child theme `theme.json` merges over the parent, it does not replace it.
- Global Styles saved by users override everything; "Reset to defaults" in the editor
  removes them. During development, reset often to see the real theme output.
- Do not use theme.json to register blocks, patterns, or menus. Not its job.
